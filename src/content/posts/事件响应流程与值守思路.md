## 学习目标

初级蓝队最容易犯的错误，是看到一个恶意 IP 或一句“疑似攻击”就立即封禁，却没有先确认资产、时间、请求内容和影响范围。事件响应不是单点操作，而是一条可以被复核的证据链。

NIST 在 2025 年发布的 [SP 800-61 Rev.3](https://csrc.nist.gov/pubs/sp/800/61/r3/final) 将事件响应放进 CSF 2.0 的整体风险管理中。对护网值守来说，可以把工作简化成：

1. 准备：明确资产、日志、联系人和处置权限。
2. 检测与分析：判断告警是否真实、是否成功、影响多大。
3. 遏制：在保留证据的同时阻止风险继续扩散。
4. 根除与恢复：清除落地物、修复入口、验证业务恢复。
5. 复盘改进：沉淀 IOC、规则、时间线和改进项。

## 一、接到告警先问六个问题

| 问题 | 要确认的内容 |
| --- | --- |
| 谁 | 源 IP、目标 IP、账号、主机名、进程用户 |
| 何时 | 告警时间、日志时区、首次与最后一次出现时间 |
| 哪台资产 | 业务名称、负责人、是否互联网暴露、资产等级 |
| 做了什么 | URL、命令行、文件、进程、域名、端口 |
| 是否成功 | HTTP 状态、响应长度、进程创建、文件落地、账号变化 |
| 影响范围 | 单机还是多机、单账号还是横向扩散、是否触及核心数据 |

只有源 IP 命中威胁情报，不能直接等同于入侵成功。扫描器、共享出口、CDN 和云主机都会产生误报。应优先寻找“攻击动作之后的结果证据”，例如 Web 进程拉起 shell、异常账号登录成功、计划任务创建或可疑外联。

## 二、事件分级的简单做法

我给初级值守设计了一个四维评分：

```text
事件优先级 = 资产重要性 + 行为可信度 + 影响程度 + 扩散可能性
```

- P1：核心资产已确认失陷、勒索扩散或大量数据外传，应立即升级。
- P2：高危攻击已成功，但影响仍局限在少量主机。
- P3：攻击尝试或可疑行为，暂未找到成功证据。
- P4：误报、合规提醒或低价值扫描。

分级不是为了给事件“贴标签”，而是决定谁来处理、多久响应、能否先封禁以及是否需要业务负责人介入。

## 三、护网告警处置 SOP

### 1. 保存原始信息

先记录告警 ID、原始日志、查询语句和时间范围。不要只留截图，因为截图不便搜索，也可能漏字段。对导出的文件计算哈希：

```powershell
Get-FileHash .\exported-event.evtx -Algorithm SHA256
```

Linux 下可使用：

```bash
sha256sum exported-log.tar.gz
```

### 2. 补齐上下文

围绕告警时间前后至少 5～30 分钟查询：

- 同一源 IP 还访问了哪些资产；
- 同一目标资产是否出现异常进程、登录和外联；
- 同一账号是否在不同位置登录；
- 相同 URL、文件哈希或域名是否在其他主机出现。

MITRE ATT&CK 的 [Data Components](https://attack.mitre.org/datacomponents/) 提醒我，单一日志往往不够。进程创建、网络连接、DNS、文件和账号活动需要互相印证。

### 3. 判断成功与否

以 Web 攻击为例：

```text
请求命中高危特征
  ↓
目标返回异常内容或状态
  ↓
Web 服务进程创建异常子进程
  ↓
主机下载文件或连接外部地址
```

只出现第一步，通常只能写“攻击尝试”；出现后三步中的任意一项，就应提高优先级并扩大排查。

### 4. 遏制但不破坏证据

处置动作按影响从小到大排列：

1. 封禁明确恶意 IP、域名或哈希；
2. 禁用被盗账号、吊销会话与密钥；
3. WAF 临时阻断恶意路径或参数；
4. EDR 隔离失陷终端；
5. 网络侧隔离服务器；
6. 经批准后下线业务。

在未获得授权前，不擅自删除文件、重启核心服务器或清空日志。

## 四、事件记录模板

```text
事件标题：
发现时间：
告警来源：
涉及资产与负责人：
事件级别：

现象：
关键证据：
影响判断：
已执行处置：
待执行处置：
当前结论：

IOC：
- IP：
- Domain：
- URL：
- Hash：

时间线：
- 10:01 首次攻击请求
- 10:03 出现异常进程
- 10:07 完成网络隔离
```

结论要区分“事实”和“推测”。例如“日志显示 `w3wp.exe` 于 10:03 创建 PowerShell”是事实，“攻击者可能获得 WebShell”是推测，需要更多证据支撑。

## 五、复盘时检查什么

- 日志是否覆盖攻击发生的完整时间段；
- 告警是否过晚、规则是否缺少上下文；
- 资产台账、联系人和处置权限是否准确；
- 封禁是否存在业务误伤；
- IOC 是否同步到其他检测设备；
- 漏洞、弱口令或错误配置是否真正修复；
- 是否形成新的查询语句、检测规则和操作手册。

## 本篇小结

初级蓝队的价值不是“封了多少 IP”，而是能否快速回答：发生了什么、是否成功、影响谁、证据在哪、下一步做什么。规范记录和多源关联，比盲目追求工具数量更重要。
